# H2G2 — hyperlocal guide for a Marswalk in Gale

Team **DETON8** · NASA Space Apps Challenge, Salvador 2026.

Hyperlocal map of the boxwork region on Mount Sharp (Gale Crater),
with smart routing, safety alerts and a science card —
designed as a field guide for the astronaut during a walk
(Marswalk), running **without depending on internet** (real
Mars-Earth delay: 4-22 min). Why Gale and not Jezero, judging
criteria and the central pitch argument are in
[`docs/H2G2_Proposta_Projeto_Planejamento.md`](docs/H2G2_Proposta_Projeto_Planejamento.md)
and [`docs/PITCH.md`](docs/PITCH.md).

## Running

### API + map (features 01/02/08)

```bash
make build   # once, with internet: dependencies + real data in data/local/
make run     # API and map at http://localhost:8000
```

Local agent (`/api/ask`): install [Ollama](https://ollama.com) once. `make build`
downloads the `gemma3:4b` model (3.3 GB) into `data/local/ollama/`, and `make run` starts
Ollama reading from that folder. The model stays out of git (it exceeds GitHub's limit). Moving the package to another machine
still does not work just by copying `data/local/` (see item 5 of `docs/raio-x-implementacao.md`).

Without `make` (Windows): `cd api && pip install -r requirements.txt && python -m uvicorn main:app --port 8000`
and open http://localhost:8000. There is no `npm install` and no front build.

### F03/F04 (panorama and science card)

`make build` already runs the ETL (`data-pipeline/f03/etl/build.py`). It writes the tables
`photos`, `panoramas`, `targets`, `measurements` into `data/local/h2g2.sqlite` and the files into
`data/local/f03/` (served at `/bundle`).

## Map layers

Full record (decisions, sources per purpose, calculations, validations and what was discarded): [`docs/feature-01-camadas-de-dados.md`](docs/feature-01-camadas-de-dados.md).

| Layer | Type | Source | Resolution | Confidence | Limit |
|---|---|---|---|---|---|
| CTX / HiRISE | optical | Mars Trek (WMTS) | ~10 m / ~0.6 m | measured | black and white only in Gale |
| Relief | topographic | Gale HiRISE DTM | ~5.9 m | measured | fixed light from the northwest (convention), not the real Sun |
| Slope risk | topographic | DTM × slope measured by the rover | ~5.9 m | estimated | historical frequency, not a forecast ([F06](docs/feature-06-previsao-clima.md)) |
| Thermal inertia | thermal | THEMIS, USGS quantitative mosaic | 100 m | measured | ~30 cells in the crop; multi-year |
| Atmosphere (REMS on the trail) | atmospheric | REMS (PDS), 1 point per sol | point | measured | only where the rover stopped; mixes place and season; PDS up to sol 4843 |
| Direct sun and shade | illumination | Mars24 + 1 m DTM + MOLA | 2 m (validated at ~10 m) | inferred | see below |

**Direct sun and shade.** For the chosen solar time ("now" and "arrival" shortcuts, with a simulated clock: `H2G2_CLOCK="SOL@HH:MM" make run`), paints Sun incidence and relief shadows. The destination is classified by the ~20 m area around it: in sun, partial shade or in shade.
- **Validated against HiRISE photo PSP_009294_1750:** Sun position (≤ 0.1°) and lit × dark side of the relief at ~10 m (correlation +0.38; controls with the wrong Sun, negative).
- **Not validated:** shade at an exact point (the fine darkness in the photo comes from ridges < 2 m) and shade with a low Sun (there is no HiRISE photo outside 14h–16h).
- **Does not account for:** dust (shade receives diffuse light) and the route time error in the arrival time.
- **Use:** light orientation, not a safety criterion. Details: [`docs/feature-01-camada-insolacao.md`](docs/feature-01-camada-insolacao.md).

**Off the map:** ground temperature. The sensor (GTS) is read through channel B, which gives 35–39 °C at noon, implausible for Gale; channel A looks correct, not migrated yet ([F06](docs/feature-06-previsao-clima.md)).

## Does it work without internet? ("would it work on Mars?")

**Yes, in the sense that really matters: zero network calls at
runtime**, confirmed by an audit on 2026-11-14 (see
[`NEXT-STEPS.md`](NEXT-STEPS.md)):

- All real data is already cached in `data/local/` (~130MB in total —
  tiles, DTM/MOLA, REMS/RAD conditions, nomenclature, rover
  waypoints, and the ~200 photos, actually downloaded to disk instead
  of pointing to `mars.nasa.gov`).
- Zero network calls in any endpoint of the running API.
- The frontend (`web/`, plain HTML/JS) vendors MapLibre and the fonts
  (`web/lib/`, `web/fonts/`) -- no CDN at runtime, and no
  `npm install` (there is no `package.json` in the project anymore).

The only step that needs internet is **preparation**
(`pip install`, the `fetch_*` scripts in `make build`) -- it happens
once, in advance, just like installing any software before a real
mission.

## React → plain HTML/JS migration: done

**2026-11-14**: the migration requested by [`CLAUDE.md`](CLAUDE.md) and
planned in [`docs/migracao-front-html-puro.md`](docs/migracao-front-html-puro.md)
was completed end to end -- `web/` is now the project's only frontend,
served by the API itself (`/`), and `frontend/` (React)
was actually removed from the repository (confirmed: it no longer exists
on disk nor tracked by git).

Validated live after the removal: `/` serves `web/`, `/api/route`
returns the 3 variants (including "most science" and real radiation,
built before the migration), `/api/point` with alerts, `/tiles` and
`/rover-photos` -- all working together, nothing broke in the switch.
