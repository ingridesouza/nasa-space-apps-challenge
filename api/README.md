# api

Endpoint `GET /api/point?lat&lon` described in
`feature-01-mapa-hiperlocal-boxwork.md` (section 3.2). Contract
reused by feature 02 (route/A*, Hugo) and feature 08 (voice
assistant) — schema changes here must be agreed with the team before
being applied.

## Running locally

```bash
pip install -r requirements.txt
python -m uvicorn main:app --reload
```

Test: `http://127.0.0.1:8000/api/point?lat=-4.59&lon=137.44`

## Status

- ✅ **Raster sampling** (elevation + slope): actually works for
  any layer of type `single_raster` in `raster_registry` (today:
  HiRISE 1m DTM and MOLA). Slope computed by finite differences on a
  3x3 window — simple, not an "official" slope algorithm, but it uses
  real elevation data.
- ✅ **Nearby photos and science target**: radius search via SQLite's
  native R-Tree on the F03/F04 tables (`photos`, `targets`,
  `measurements`), generated by `data-pipeline/f03/etl/build.py`.
- ❌ **`tiles_wmts` layers** (CTX, HiRISE optical, THEMIS) are not
  sampled — they are PNG tiles without individual georeferencing, they
  would need to become a georeferenced mosaic first (out of MVP scope).

## Local database

Schema and population scripts live in `../data-pipeline/db/` (schema
shared between the ingestion pipeline and the API). Run
`python data-pipeline/db/populate_raster_registry.py` after downloading
new raster layers.
